# Local memory specialists and character life state

The `reign-memory-specialist-v1` index is a rebuildable search aid for accepted original conversation turns. It stores original source hashes, authoritative speaker and audience, exact name mentions and broad topic facets. A mention is not an actor, recipient or commitment. Ambiguous names remain unresolved. Extracted text, identity and metadata never replace original dialogue.

The maintenance sweep indexes both recent and old originals independently of remote summaries and vectors, yielding between sources for foreground work. Retrieval still enforces source-content, observer, as-of day/sequence/time and restored-source membership. Public facets derive from listener-visible text; private thoughts cannot promote a source for another observer. Missing/stale annotations do not exclude lexical or semantic results. Precision and legacy retrieval share the index.

PostgreSQL source-row revisions provide cheap rebuild hints; full content/metadata hashes remain the retrieval authority. Qualified extractor upgrades have a separate maximum of four sources per maintenance pass. Each source/model revision allows four attempts with increasing backoff; deterministic indexing does not consume that budget. A cold-load timeout can recover later without delaying a dialogue response. A changed source or qualified model starts a new bounded attempt series.

Original-source bundles retain adjacent spoken clarifications with the preceding claim and actual response even when no question was asked. Visibility and as-of checks apply before linking; hidden turns cannot be skipped to invent adjacency. This context is not an automatic finding that an objection was resolved or a correction accepted.

## Optional local extraction

The loopback vector worker accepts `POST /memory/extract` with `sourceId`, `text` and its SHA-256 `textHash`. It returns bounded original UTF-16 spans, candidate entity types/topic labels, schema/model hash, cache/latency/coverage status and `remoteCalls: 0`. No returned field executes actions, changes relationships, resolves ambiguous pronouns, or promotes traits. Long sources use overlapping exact-text windows; incomplete coverage is explicit. Malformed, mismatched, oversized, busy and unavailable requests are not successful extractions.

The adapter requires an installed local GLiNER2 model at `REIGN_MEMORY_EXTRACTOR_MODEL_DIR`. Requests never install dependencies or download models. The experimental public model is `fastino/gliner2-base-v1`, revision `f9634218e53580c56edf0de97ca1a7d3f1c2354e`. Development uses `gliner2==2.0.0`, `transformers==4.57.6` and CPU torch. These identifiers are not qualification: activation requires a reproducible dependency/model environment, source-labeled semantic quality and latency/contention evidence. `enableLocalMemoryExtractor` defaults false; `localMemoryExtractorQualifiedModelHash` must match the evaluated files before annotations are accepted. This does not change dialogue or ordinary memory-summary profiles or silently substitute a model.

Only local safetensors and the known DeBERTa encoder are loaded; custom model `auto_map` code is rejected. Cache identity includes schema, model files and source text; source IDs are rebound on each read. The server enforces source access independently of model labels. The endpoint belongs on the existing loopback boundary, never an unauthenticated public service. Worker health reports extractor availability separately from the embedding model.

## Life transitions

`reign-character-life-state-v1` projects committed decision receipts and completed personal native events into protected dynamic character context. Accepted allegiance and explicitly life-changing decisions retain original speaker evidence, terms, reservations and reconsideration. Ordinary favors or isolated intimacy do not automatically create permanent commitments. Accepted intention is not native recruitment, transfer, payment or marriage. Coerced compliance differs from willing loyalty. Later supported decisions supersede earlier ones without erasing history.

Readback verifies original turns or authored letters, receipt state, audience and chronology. Completed personal events do not imply invented emotions. Individual, party, social/event, tavern, correspondence and official routes use the shared context; the official firewall excludes private agreements. Native events remain history when present circumstances change. The writer should remember commitments without reciting them each turn.

Derived rows reuse `dynamic_characteristics` with category `life_transition`; ordinary soft-character selection excludes this category before ranking. Maintenance refresh writes projections in its own transaction. Prompt reads do not write or trust those caches as authoritative evidence. A failed helper logs unavailable/deferred status, preserves ordinary conversation, and cannot justify a penalty or action execution.

Rankings, confidence and more retrieved passages are not accuracy certificates.

The existing isolated `memory_evidence_replay` accepts optional top-level booleans `indexSpecialistSources` (default false) and legacy `analystEnabled=false`. The first builds deterministic metadata for fixture originals; remote memory stages are retired, and an enabled analyst flag is rejected. The result records indexed source hashes, fixture-plus-index time and enabled state. It never loads an extraction model, contacts a worker/provider, grants a qualification certificate or modifies a live campaign. Only exact source/model/request-bound local captures may enter the replay; completion alone does not certify model quality.

To measure enabled GLiNER end to end, run the pinned local extractor separately on the frozen originals, then supply `enableLocalMemoryExtractor: true`, `extractorModelHash` and per-case `capturedMemoryExtractions`. Every original requires one `{sourceId,textHash,result}` capture, including real failures. Successful results must match the selected model, original ID/hash, schema and UTF-16 encoding before IDs are rebound into the disposable fixture. Production document validation, indexing, observer projection, retrieval and writer prompt assembly then run unchanged. Results retain accepted documents/public facets, rejected spans, model identity and capture hashes. Compare identical originals, queries and writer settings with the flag absent; keep writer, originals and query settings identical in that comparison. Capture input is bounded to 512 originals and 8 MiB per case inside the existing 32 MiB file limit; the rest of each case retains its 1 MiB limit. This is an enabled extraction replay, not live worker lifecycle proof or a production qualification certificate.

## ColBERT original-source discovery

The existing loopback worker exposes `POST /memory/late/index`, `/memory/late/search` and `/memory/late/status`. These are local internal endpoints, not public APIs or model tools. Index requests carry a campaign, exact source/view hashes and observer-projected text; search requests contain a query and the exact eligible source/view hashes, never the whole archive. Limits are eight indexed views per request, 32,000 characters/128 complete windows per view, 50,000 eligible sources and 128 returned candidates. Oversized/incomplete input is rejected rather than silently clipped. Search has a two-second scoring budget and bounded HTTP fallback. The model cannot execute actions, select relationship numbers, alter identity or grant another observer private knowledge.

Pinned `colbert-ir/colbertv2.0` revision `c1e84128e85ef755c096a95bdb06b47793b13acf` uses the published ONNX graph, 128-dimensional normalized token vectors, query/document markers, mask augmentation, punctuation masking and overlapping 177-token source windows. The exact assets are in `release/embedding-model.lock.json`; installation retrieves them once through the managed runtime preparer. Requests never download models. The CPU runtime uses the already pinned ONNX/tokenizer/NumPy dependencies. This is exact MaxSim discovery with persisted float16 vectors, not the PLAID compressed/approximate index or the RAGatouille package. Model license: MIT; upstream [model](https://huggingface.co/colbert-ir/colbertv2.0) and [ColBERT](https://github.com/stanford-futuredata/ColBERT).

`data/vectors/late_interaction.sqlite` is a rebuildable cache outside campaign history. Each original has separate self/public views. Publication replaces all windows atomically; source metadata hashes, PostgreSQL row revision, model/schema and a persistent worker-index generation bind server receipts to the cache. A deleted/replaced index is rebuilt. Old and recent sources receive bounded maintenance; foreground inference takes priority between chunks. Per-source failures have at most four attempts per source/model/schema revision and five-minute backoff. Missing models and index/search failures preserve existing retrieval and dialogue. Unindexed sources remain eligible for other search paths; partial coverage is reported separately.

Both legacy and precision routes discover ColBERT candidates beyond the lexical shortlist. Eligibility precedes scoring, and selected original content/projection is reloaded and verified afterward. Rank fusion uses rank positions, not incomparable numeric scores. Complete original exchanges and clarification/answer links remain the evidence authority. `memoryLateInteractionMode` accepts `off`, `shadow` (default) or `on`. Shadow records candidates without changing the writer's selected evidence. `on` requires `memoryLateInteractionQualification`: schema `reign-colbert-qualification-v1`, matching `indexSchema`/`modelHash`, a pinned `corpusSha256`, `heldOut` and `independentlyLabeled`, at least 100 cases, zero critical errors, required-evidence and answer coverage at least 0.98, quality and answer coverage no worse than baseline, and retrieval p95 at most 2,000 ms. All coverage/quality fields must be finite fractions. Contracts or development rankings cannot supply this certificate.

The isolated replay optionally accepts boolean `captureLateInteraction` and `precisionMode` (`legacy`, `shadow`, `precision`). Captures export production-approved observer views and exact query/hash requests; no worker runs in the verifier. Optional per-case `capturedLateInteractionSearches` (at most 24 distinct queries) supplies model/schema, query and at most 128 unique original-source results with view, textHash and finite score. Results bind to identical query and projected text before IDs are rebound into the disposable fixture. Missing/mismatched captures remain pending. `lateInteractionReplay` and `lateInteractionAudit` preserve evidence/coverage; model performance must be measured separately against the exported inputs. This never authorizes providers or qualifies a production model.
## Local selection and packing implementation, 2026-09-30

The user selected Qwen3-Reranker-0.6B instead of MemReranker and authorized LLMLingua-2 compression. Both use pinned local ONNX conversions. Explicit preparation preserves the pinned Q4 weights, converts floating tensors to FP16 and retains only last-position no/yes logits. This derived graph requires its own qualification; parity of an earlier INT8 output-head experiment does not certify the Q4/F16 conversion. LLMLingua keep-token probabilities rank whole optional narration spans. Reign never publishes model-generated replacement text.

`memorySelectionMode` supports `off` (default), `shadow`, and `on`. The former `enableMemoryPrecisionCrossEncoder=true` maps to on only when the new mode is absent; it still requires the new qualification and does not issue the old MiniLM call. `memorySelectionTimeoutMs` defaults to 15,000, bounded 500–30,000. `enableMemoryEvidenceCompression` defaults false. Missing qualification prevents on-mode inference and reports `held_out_qualification_required`; off makes no requests. Explicit shadow mode measures ranking without changing writer evidence. Replay mode requires the isolated Verification Lab and an injected source-bound responder.

Qualification binds `runtimeVersion=1.22.0`, `rankingPolicy=complete-source-window-max-v1` and `runtimeBackend=cpu` or `cuda`; worker receipts must match. Shadow/replay use explicit `memorySelectionBackend` (default `cpu`). CUDA ranking has a 2 GiB arena limit, with context/driver overhead additional; no silent CPU substitution is accepted. BGE, ColBERT and LLMLingua remain on CPU. Cold loading counts toward the 15-second default deadline; measured startup is separate from warm scoring. Variable-length GPU runs release unused arena regions after each inference.

Whole records up to 2,048 query/document tokens use one score. Longer originals use at most 16 overlapping source slices with a 192-token overlap and complete coverage; every slice must finish before publishing the strongest relevance score. A fragment score is not a factual verdict. Exact full linked source text remains the candidate and the writer's evidence. Receipts bind the policy; `scoringCoverage` reports window count and UTF-16 source ranges. The server rejects missing coverage, gaps, truncated tails, repeated windows and split surrogate pairs. Excess windows/query size, unavailable CUDA, memory pressure or deadline keep the ordinary evidence; never score just a prefix or publish partially completed ranks. Source fences hash exact UTF-8, not normalized prompt text.

The `memorySelectionQualification` certificate uses `reign-memory-selection-certificate-v1`, `pipelineSchema=reign-memory-selection-v1`, exact `rankerHash`/`rankerTokenizerHash` and a hexadecimal `heldOutCorpusSha256`. It requires `heldOut`, `independentlyLabeled`, at least 100 cases, zero `criticalErrors`, finite 0–1 metrics, at least 98% `requiredFactCoverage` and `answerCoverage`, no answer regression against `baselineAnswerCoverage`, and `quality>baselineQuality`. The existing latency gate remains `0<rerankP95Ms<=1.2*baselineP95Ms`, measured across an explicitly identical boundary. Compression additionally requires matching compressor/tokenizer hashes, `compressionEvaluated=true`, and zero `lostProtectedSpans`. Development captures cannot supply this certificate.

The first complete ranked bundle can use the configured older-evidence allowance when it exceeds the 2,000-token fallback floor. Its raw binary score is not treated as a cross-query 0.5 certainty threshold. A supplementary pass can use remaining configured space without evicting the first pass. Missing validated scores retain the ordinary fallback. Required evidence, explicit smaller budgets and final writer capacity remain authoritative. Unused space in a protected-history growth reservation cannot expand the configured ordinary allowance; this applies with and without ranked results. Complete final-request coverage and generated dialogue quality must still be measured separately.

Packing compares canonical source hashes and exact authorized observer-view hashes separately. Identical transcript views no longer consume older-memory budget twice; a changed speaker/text cannot suppress evidence. Equivalent bundles merge before ranking. Relevance has its own ordinal, avoiding comparison with arbitrary untouched priorities. Protected context below8k also leaves a2000-token older-evidence allowance. Rejection audits retain priority, ordinal, available budget and compact-view availability.

The ranking query retains bounded prior dialogue for references and ends with the current contribution as its explicit target. A topic change must not make unrelated prior discussion the selection target. The local development replay exposed this in the Ira plant clarification. Original sources and writer budgets stayed fixed; selected-answer coverage is measured in the serialized writer request, separately from relevance scores.

Recent30messages,30compact summaries, required records, exact-wording requests, every spoken span and source label stay intact. Optional older narration is conservatively protected for query terms, negation, conditions, time and consequential transfer/drink/intimacy/commitment/recall actions. Other narration may be omitted only as whole source spans. A compact view is used only when its complete record cannot fit. An explicit omission marker and partial-coverage audit prevent treating the excerpt as complete; original database sources remain unchanged. These conservative guards are not general semantic proof.

Explicit verbatim, quotation, complete-text or every-gesture requests keep original narration. Generic factual question words such as where/when, including those inside player motion, do not by themselves prohibit safe background extraction. All spoken words, speaker labels and consequential narration still remain protected.

Unknown/duplicate/nonfinite/incomplete rankings, mismatched hashes, unavailable files, lock contention, timeout and invalid protected-span selections keep original evidence. Failures create no relationship or native-action effect and never replace dialogue. Applied versus shadow status, model hashes, operation timing and compact views are observable separately from total retrieval and writer time.

`compressionViewsPrepared` describes available compact alternatives. `compressionApplied` and `compressionSelectedSourceCount` are finalized after allocation and count only compact views actually selected; preparing an unused view is not a token saving.

Compression requests are conditional on the ranked allocation: only whole records rejected for lack of space qualify, and their protected-span minimum must fit the remaining allowance. Fitting originals and records that cannot fit even after safe extraction make no compressor request. At most eight feasible candidates are requested. Shadow predicts allocation on copies. This avoids the measured 56 unused compression calls in the 100-case development of the adapter, without weakening source protection.

# Validation and deployment checkpoint, 2026-09-30

Installed acceptance exposed a shared-queue hazard: loading and updating the existing 1.48 GB local Qdrant collection can occupy its operation gate for minutes. ColBERT now owns a separate inference gate, retaining foreground priority between its bounded chunks and a one-second foreground queue-wait limit. It never waits for unrelated Qdrant storage maintenance. The CPU encoder remains limited to two inference threads. Worker health reports this gate separately. A busy ColBERT model still returns an explicit fallback; its query cache remains serialized. This isolates the new helper but does not fix the older Qdrant startup/delete cost. Real game contention and large-store BGE startup remain separate performance work.

Canonical Reign source fences use uppercase SHA-256 while the worker's own text digests use lowercase. The worker accepts both hexadecimal forms and preserves the exact supplied source fence. Worker and packaged-inference regressions cover an uppercase canonical fence and rejection of a changed fence; no identity/source authority moves into the model.

Long-history eligibility uses an explicit SQLite join order: approved source identities drive exact index lookups before token-vector loading. A synthetic 3,000-source probe exposed quadratic allowlist rescans in an ordinary join; a VM-instruction scaling contract prevents recurrence without a wall-clock test. This preserves identical eligible records and MaxSim scoring. Larger corpus/game-contention acceptance remains separate.

Legacy anchor selection now uses reciprocal rank fusion when specialist or qualified ColBERT discovery contributes. Sole ColBERT ranks remain ordered through later evidence allocation. Exact protected transcript hashes are stored with canonical row revisions and excluded before semantic top-k, so the recent window cannot exhaust older recall slots. Selected originals are still reloaded and checked after search.

The packaged worker release proof performs local ColBERT inference and index reopen with network access disabled. It also checks a private original is excluded before ranking. The proof is deliberately not a semantic qualification certificate. The model's MIT notice ships under release/ThirdParty.

Captured replay accepts numeric finite scores only, rejects changed models/projections, and leaves missing queries pending. Linux Verification Lab can read the three explicit replay input filenames beside the validated artifact, with the existing CLI/isolation and size guards; its outputs remain isolated. No production source or historical memory changes are authorized by a replay input.

## ColBERT scoring and deferred indexing, 2026-10-02

Complete-window MaxSim scores all document and query tokens in 32-query-token matrix tiles, then sums the maxima once in the original query order. This avoids the observed CPU BLAS slowdown for long queries without changing process-wide thread settings, source eligibility, model/schema identity, or the two-second scoring budget. Small floating-point differences from matrix shape changes require reference-score tolerance and ranking parity checks; this is not a new relevance policy. Every persisted source window must be present before search succeeds. Missing later windows, nonfinite/invalid query vectors, and expired scoring budgets return no ranks. Search timing includes eligible lookup, query encoding/queue time, scoring, query-token and scored-chunk/source counts, tile size and scoring allowance, including on timeout.

The existing 60-second background maintenance timer revisits index work after bounded worker backoff (5, 15, 60, then at most 300 seconds). No blocking delay or immediate HTTP retry is introduced. Startup/transport errors and declared transient worker contention defer the batch without spending the four-attempt source-content budget. Successful maintenance resets worker backoff; a changed worker endpoint is not held by the previous endpoint's cooldown. Permanent source/model or malformed-receipt failures retain the existing four-attempt, five-minute source backoff. A source is published only when all expected view receipts match its exact identities and hashes; incomplete receipts cannot erase its failure status or mark it complete.

Deferred diagnostics report the failing phase, typed transport/inner error, HTTP status where available, and retry allowance. Worker failure reasons pass an explicit allowlist; exception messages, response bodies, URLs and original dialogue are excluded. Source failures have a separate bounded operational event. Diagnostics failures cannot break dialogue. Isolated Verification Lab uses an injected index/status adapter and disposable campaign only; no adapter means no worker dispatch. No historical records, live settings, retrieval qualification, provider routing or relationship effects change.

Validation distinguishes deterministic failure/privacy/persistence contracts, reference numerical/ranking parity, local timing with retained vectors and pinned encoder, installed startup/recovery, and native game contention. Isolated speed results do not certify conversational accuracy or authorize activation from shadow mode. Preserve initial failed runs and report cold load separately.
