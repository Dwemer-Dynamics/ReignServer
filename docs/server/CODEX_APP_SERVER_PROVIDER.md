# Codex app-server provider

## Failure recovery and availability checks (2026-10-14)

Official `account/updated` notifications report authentication mode and plan without an account ID or email. Reign retains the last verified identity and checks `account/read` before acquiring the next thread after a partial notification. A verified account switch, sign-out, authentication-mode change or unidentifiable account retires reusable threads. A plan change alone does not change identity. Metadata-read failure stops before inference. The production fixture injects real-shaped notifications during accepted turns, verifies reuse across a plan change and forces a fresh thread for a different account in the same authentication mode. Final diagnostics report whether a thread was retained or retired, contract-change reason and usage evidence.

A terminal failed Codex turn with HTTP 429 and no partial output may receive one delayed retry: at most two total generations, preserving the complete request, model, reasoning and processing tier. The delay is at least two seconds and respects a supplied retry hint up to 30 seconds, the original deadline and physical-call budget. Explicit allowance exhaustion, partial output, cancellation, campaign replacement and ambiguous dispatched timeouts do not automatically replay. Public limit metadata is read after a failure; absent metadata does not establish quota exhaustion. Structured provider failure details remain in diagnostics and status.

Individual Chat retains the original failed text, action draft, correlation and scene-turn IDs. Its error remains visible and the empty-composer Send button becomes Retry. A retry serializes with the original logical turn and checks for an already-saved answer before generating; an existing answer reloads history instead. New text starts a new turn. Save/load or conversation scope changes invalidate the local retry snapshot. No technical diagnostic becomes NPC speech or authorizes an effect.

The Control Center's **Model to check** is an availability diagnostic only. It starts from the Codex Dialogue model and remembers edits in browser-local storage across saves and reloads. Set conversation models on the Models tab. Saving, reloading and catalog discovery never send verification requests; the explicit check remains confirmation-gated and limited to one generation.

Prompt-cache status returns a bounded metadata projection and its browser display is capped. Complete immutable conversation evidence and the actual game prompt remain unchanged. This avoids rendering megabytes of selected memory and transcript diagnostics during tab changes or settings saves.

Provider-free recovery proof uses `contracts.codex_runtime`, injected production transport cases, `contracts.conversation_failure_recovery`, `ConversationRetryTests`, the Control Center browser contract and `test-generation-retry-contract.mjs`. Native Retry acceptance remains a separate post-deployment check.

Reign supports two chat-provider selections in the Control Center:

- `NanoGPT / OpenAI-compatible` keeps the existing HTTP chat-completions path, URL, API key, caching, retry, and circuit-breaker behavior.
- `ChatGPT Codex subscription` starts OpenAI's published `codex app-server` as a local stdio JSON-RPC child process and uses the account authenticated by that official runtime.

## Safety and lifecycle

Reign does not proxy OAuth, read Codex credential files, or store ChatGPT access or refresh tokens. Browser sign-in is initiated through `account/login/start`; the official Codex runtime owns the resulting authentication state. The child process is assigned to Reign's unified Windows lifetime job and is also stopped during orderly server shutdown.

Structured character conversations retain an official app-server thread across accepted turns. The first turn receives the complete current game prompt. Later turns receive the current engine reference context and latest player contribution after the accepted history signature is checked. The game prompt builders, response schemas, repairs and action validation remain authoritative. Engine-added decision/motive diagnostics do not count as edits to the validated model contract; dictionary ordering is ignored. The server's independent political-conduct classification may replace model metadata only when the accepted enforcement receipt proves the exact original reply was unchanged and the final classification matches that receipt. Only the authoritative date/venue heading is allowed to change the accepted visible reply without retiring its thread. Unstructured/custom envelopes and other requests keep their existing fresh-thread path unless separately eligible for experimental reuse.

Thread identity includes campaign/load generation, conversation session/mode, responding character, visibility, stable game rules and character reference, exact model/reasoning and output contract. A changed identity, rejected/repaired response, divergent accepted transcript, missing usage, observed compaction, capacity limit or failed resume retires the thread. The next generation uses the newly assembled full game prompt and current memory selection, never a cached initial retrieval subset. A failed resume before generation falls back to the full current input; an ambiguous dispatched turn is not replayed by this adapter.

`codexOptions.lookupMode` is `auto` (default) or `direct`. Auto retains the game's existing automatic memory selection. Direct keeps that starting context and adds `search_character_record` and `read_character_record` over the character's accessible original conversations, memories and letters. Character reference reads use the same supplied, identity-projected game reference. These two read-only tools have a four-attempt turn budget, bounded results and paged originals. Model arguments cannot select campaign, owner, timeline, database, SQL, file path or network endpoint. Shared knowledge, observer projection, future/branch visibility, correspondence receipt and official-memory firewalls apply before evidence is returned. Save loads invalidate even cached tool snapshots. Lookup failure is not proof that the character has no memory.

All requests use `approvalPolicy: never`, a read-only sandbox and a dedicated empty working directory. Shell, web, apps, code mode, image generation and delegation are disabled in request configuration. Reign rejects interactive approval and other server-initiated tools. Direct's experimental app-server tools use an explicit developer retrieval instruction and preserve game rules; they are not available to arbitrary `/llm/chat` callers. Completed temporary and retired reusable threads are deleted through bounded cleanup. Thread reuse is limited to 32 turns, the verified model input allowance, 64 pool entries and 10 minutes idle; incomplete usage prevents reuse.

## Configuration

2026-10-13 context correction: Codex capacity comes from the official runtime's exact-model `models_cache.json`, bound to its selected `CODEX_HOME`. Reign reads no authentication file. Fresh unique metadata supplies `context_window` and `effective_context_window_percent`; missing or expired metadata triggers a bounded, throttled `model/list` refresh without inference. Prompt assembly and final dispatch share that policy, including helper, repair and construction requests. Reserve the configured output, 1,024 safety tokens and 16,384 runtime/tool tokens. Codex inputs use the disclosed conservative token estimate; its own tokenizer and compaction enforce the actual window. UTF-8 byte length remains a diagnostic instead of falsely counting one token per byte. HTTP-provider byte-bound behavior remains intact. The legacy character ceiling expands only after the complete request passes the selected-model policy. Unknown/invalid metadata, missing required evidence and oversized requests still fail before dispatch. Explicit route certificates retain their expiry and route scope. No game prompt or selected memory is truncated to fit.

Persistent chat reuse now takes the verified model's input allowance rather than always retiring at 128k input tokens. The 128k fallback applies only when no model allowance is available; the 32-turn, 64-entry, ten-minute-idle and compaction/rewrite retirement rules still apply. Verification injects metadata and never reads a user's cache or starts their runtime.

The default executable is `codex`, resolved by the service process. A full path can be entered when the official runtime is bundled outside `PATH`. `CODEX_HOME` is optional; blank preserves the official runtime default. Settings must be saved before starting or signing in.

The Control Center can start/check the runtime, open the official ChatGPT sign-in URL, sign out, and refresh `model/list` with `includeHidden: true`. Selecting Codex with an empty catalog automatically discovers models, without generating a response. The picker preserves selection on refresh and retains its last catalog on discovery failure, with an actionable error. Every returned model is available as a picker entry and suggestion; catalog inclusion is not proof that a particular account can complete inference on that model. Discovery accepts runtime model/id/slug identifiers and retains reasoning capability metadata.

## Provider flow

The Codex reasoning dropdown follows the actual Dialogue model's advertised efforts, including Max and Ultra where available. Applying a catalog model to all request types updates those choices. A valid saved level is retained; an unavailable level changes to the nearest lower supported level, or the lowest level if none is lower. Unknown capabilities preserve the requested level. Other request models resolve their own capabilities independently, and selective reasoning retains its existing direct-repair and low-memory policy. Off requests no reasoning where supported, otherwise the model's lowest advertised level. API-provider reasoning settings remain separate. Injected production wire tests cover each effort and all/selective/off policies without generation calls.

1. Reign starts `codex app-server --listen stdio://` and sends `initialize` followed by `initialized`.
2. Account controls use `account/read`, `account/login/start`, and `account/logout`.
3. Model discovery pages through `model/list` until no cursor remains.
4. Chat requests use `thread/start` or a verified `thread/resume`, then `turn/start`, collect agent-message notifications, require a completed turn, and adapt the final text to Reign's existing provider response contract. Direct uses the experimental API handshake for the two scoped tools.

Stdio requests use one LF-delimited JSON frame per message. Reign escapes non-ASCII UTF-16 code units as JSON Unicode escapes before writing the frame, preserving multilingual prompt text while avoiding transport corruption from raw smart punctuation, emoji, or other campaign text. Provider status reports the last method, frame character/byte counts, write timestamp, and framing mode without recording prompt contents or credentials.

Querying status does not start the runtime. Selecting/loading Codex with an empty catalog can start the official child for model discovery; discovery never consumes a generation call. Provider-backed tests remain separately gated by the Verification Lab `live-llm` tier.

Provider-free contracts cover current-context deltas, full fresh input after compaction or expired resume, nested production usage receipts, stable identity despite bookkeeping updates, original-record visibility, load invalidation, tool scope/budget and JSON-RPC callbacks, game message parity and UI save/reload/provider-switch behavior. A two-turn production dialogue fixture verifies that the authoritative date/venue heading preserves a warm thread and that each player/NPC line appears once with its exact accepted text; the repair arm retains the normal visible repair marker. Substantive response rewrites still retire the thread. Missing campaign time and guarded certification requests expose unavailable archive coverage rather than unrestricted history. A missing native timeline resolves to main; supplied memory time fences remain authoritative. Offline results do not establish live roleplay quality, Plus usage depletion or in-game acceptance.
