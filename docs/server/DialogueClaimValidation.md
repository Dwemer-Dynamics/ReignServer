# Local dialogue claim validation

The shared integrity stage compares explicit recalled speech with observer-visible original turns. Individual, group and event dialogue already use this stage; route adapters (including child/court callers) and correspondence now use the same contract. Route-specific source eligibility remains authoritative. A letter's authored, sent or received status still comes from its record; a native action still requires its execution receipt.

## Authority and correction

The server resolves canonical speakers and addressees. It protects the latest 30 original turns and examines up to 30 eligible retrieved originals. World-day, accepted-sequence and timestamp cutoffs, private-text projections and explicit group addressees apply before matching. Duplicate authorship, uncertain speech, reported speech, hypotheses and explicitly described deception abstain. No lexical overlap or model score grants actor identity or knowledge.

The current player contribution is included before exchange storage with the same observer and whisper projection. Repeated or reported current wording defeats exclusive ownership without certifying its meaning. An unresolved current group audience causes abstention rather than an automatic correction. Correspondence uses its actual letter sources instead of treating a generation trigger as player speech. Declared deceptive intent also excludes spoken claims from automatic correction; it grants no action, relationship or durable-fact authority.

An exclusive, identity-normalized original instruction clause or complete literal quotation can prove a recalled-speaker reversal within the observed evidence. Generic unquoted factual paraphrases remain advisory: an acknowledgement does not establish who first explained a plan. Embedded phrases in denials, intentions and questions cannot prove instruction ownership. A safe first/second-person correction changes just the erroneous subject. Other proven reversals use at most one existing writer repair. Repairs retain independent metadata and invalidate effects whose quoted prose changed. An unusable repair withholds the source-proven false clause and retains useful speech. Proposed lasting writes with source-proven false attribution are withheld separately and retained in the diagnostic receipt. Historical records and relationship values are not rewritten.

Multiple-speaker summaries may propose up to eight `sourceEvidenceSpans`; normalization preserves only citation fields and the server binds each to an actual accepted original. One supported quote is never a certificate for an entire compound summary. `claimSourceCoverage.claimEntailmentVerified` remains false. Missing contribution spans mark the summary incomplete and preserve original records.

The strict conversation schemas declare these contribution citations on supported lasting-write types and `addressedHeroStringIds` on dialogue replies. Empty arrays preserve no-citation/no-explicit-addressee semantics. The provider-free schema regression covers individual, group, court, social and correspondence contracts; an unsupported new field must not cause generation failures.

Literal quotation pronouns belong to the quoted speaker. Group quotations with an unverified second-person recipient abstain. Deterministic subject-only corrections are limited to `I/You said` claims; `told/asked me` claims need a bounded writer repair so speaker correction cannot leave an inverted recipient.

## Specialized helpers

The existing loopback vector worker adds `POST /dialogue/claims/compare`, schema `reign-dialogue-claim-validation-v1`. It evaluates up to eight short original/claim pairs using CPU-only `cross-encoder/nli-deberta-v3-xsmall`, revision `a150876415327c80daeff35ca6f68f5ed8cf5c24`. The graph and tokenizer are SHA-256 pinned in `release/embedding-model.lock.json`. Each pair binds original ID/hash, claim hash and exact comparison-text hashes. Inputs exceeding 512 tokens are explicitly unresolved, never silently clipped. Two inference threads, one inter-op thread, a nonblocking lock and a 256-pair LRU bound computation. The worker accepts a 500–15,000 ms inference budget, default 8,000 ms; the server uses `dialogueClaimWorkBudgetMs` with the same range and adds 2,000 ms to its caller timeout. The 30-second unavailable backoff remains. Startup warms the model without making server health depend on it; cold-load duration is separately reported and remains within the caller's total deadline.

The classifier reports support/contradiction/unresolved at a 0.90 confidence threshold. **These are comparison hints, not semantic acceptance authority.** The server verifies score shapes, finite probabilities, pins and complete pair bindings. Incomplete, malformed, wrong-model, timeout or busy responses do not pass verification. The model cannot rewrite dialogue, assign actors, choose relationship numbers or confirm actions. No extra remote checker or analyst call is introduced. Ordinary replies without comparable explicit recall/update claims create no NLI request.

### Dedicated grounding candidate

The adapter can explicitly select `REIGN_DIALOGUE_CLAIM_MODEL=minicheck`; `nli` remains the default, and `off` disables loading. Unknown selections and unavailable selected assets fail explicitly; MiniCheck never silently falls back to NLI. `REIGN_DIALOGUE_GROUNDING_DIR` names a separately prepared candidate directory. This is an operator selection, not a remote-model or web UI option. A build or benchmark does not change the live selection.

The candidate uses `lytang/MiniCheck-DeBERTa-v3-Large`, revision `2f2d01a54fa022a7ffadb76260e1ea8bc88c82bb` (MIT), approximately 435M parameters. Published inference joins document and claim with the tokenizer EOS string (`[SEP]`) and uses softmax label 1 for support. It has no T5 `predict:` prefix, QA instructions or chat template. Our complete short pairs have one claim and no silent truncation or max-over-chunks aggregation. Scores are `unsupported` and `supported`; below 0.90 they remain unresolved. **Unsupported evidence is not a contradiction and does not prove a false claim.** Native execution, canonical identity and observer visibility remain authoritative. The server rejects binary results that masquerade as contradictions, foreign source/weight hashes, nonfinite scores or excess input coverage. Two CPU threads, a 256-token complete-pair limit, the configurable inference deadline, nonblocking gate and cache bound computation. Late inference is explicitly unresolved and not cached; scores are retained only as diagnostics. An ONNX kernel cannot be interrupted mid-call; an overrun can keep the helper busy after the caller delivers dialogue without it.

Runtime assets are full FP32 ONNX; the candidate needs no new Torch/Transformers dependency or GPU allocation:

It is not added to default installer downloads or activated merely by deploying code. After user selection and authorized activation, retain the exact tested assets in their own model-identity directory and configure the managed worker environment. Do not overwrite an embedding model version or rebuild assets for deployment. Compare Windows/Linux inference parity and cold/warm resource use against retained evidence, then perform native acceptance in a disposable campaign. Preserve the prior selection for rollback; do not rewind campaigns.

`prepare_claim_grounding.py --source-directory <pinned-local-Hub-snapshot> --output-directory <fresh-isolated-directory>` is an explicit offline development recipe. It verifies pinned local weights/config/tokenizer before loading, refuses overlapping or populated output directories, disables remote code/downloads and validates exact export fingerprints. Reproduction uses PyTorch 2.14.1 CPU and Transformers 4.57.6. Parameters are written separately without duplicating the complete model into protobuf. Use a separate process with sufficient RAM, without a concurrent heavy build. Original weights: `32ced784f4831d5f324a072e43b96d4072cac4bf41042bc42243605ffbbccbdf`. Public source acquisition is an explicit prior operation; runtime never acquires files. A fingerprint mismatch is a failed export, not permission to bless different assets.

Development comparisons tested TinyLettuce 17/32/68M, LettuceDetect 150M and MiniCheck 435/783M on a frozen manifest. The 435M FP32 candidate had fewer false accusations; default per-tensor dynamic INT8 was rejected because it greatly increased them. Recipient and native-receipt failures remain. Repeated constructed contrasts and one audited reversal do not certify held-out accuracy. The benchmark's 0.50 diagnostic threshold differs from the adapter's 0.90 hint threshold. Complete long prompts are not sent to this bounded comparator. Health and receipts expose the selected graph, weights, scoring kind and uncertified status.

`POST /dialogue/claims/extract` uses the existing local GLiNER2 model with a separate structured speaker/statement/addressee schema. Exact UTF-16 spans and model/source hashes bind proposals. Inputs are limited to 2,400 characters and 256 tokenizer tokens. The server consumes proposals only when the existing qualified local extractor configuration is enabled; it retains them as candidate/coverage evidence, not proof or automatic correction authority. The caller times out after two seconds and backs off 30 seconds. Neither extraction nor a quotation's existence establishes complete claim meaning. This build does not grant a new extraction qualification or alter live settings.

Both endpoints are local-only worker operations. They have no database access, provider dispatch, public server route, action execution or implicit model download. Assets are prepared explicitly by the managed installer. Failures cannot replace usable conversation with a negotiation notice or create a relationship penalty. Existing format, consent, negotiation and action gates retain their separate responsibilities.

## Evidence and acceptance

### Source assembly and coverage (2026-10-02)

The shared verifier extracts explicit speech recalls and additional declarative facts from visible speech and each factual lasting-write clause. Explicit subjective beliefs, hypotheses, intentions and declared deceptive prose stay distinct. Every candidate has its field/write index, content hash, offsets and an observable coverage status; no selected pairs is not successful factual verification. The eight-pair scoring bound prioritizes lasting facts and deduplicates identical comparisons. Capacity, missing evidence, unknown group addressees and oversized complete evidence remain explicit gaps. Starred narration is not treated as spoken history; excluded span hashes and offsets make this additional semantic coverage limit visible. Native actions and observer projections retain their separate validation.

Evidence assembly first binds exact write citations by ID, speaker and original content. Otherwise it ranks individual source spans, retains adjacent same-turn questions and qualifications, and supplies one complete relevant span per claim. Explicit accepted-turn question links can add a separate original question with its own audience, offsets and hash when its order and scene agree. Multiple questions or mere adjacency do not establish which question was answered. Exact model token limits remain authoritative; overflow never truncates the source or counts as coverage. Recent source views preserve native time, accepted sequence and explicit audience metadata. Natural punctuation and negation survive identity normalization. Unlinked cross-turn answers and broad paraphrase ownership remain limited; unverified coverage is not accuracy certification.

An explicit write citation that cannot yet bind remains `explicit_citation_not_yet_bound`; a similar older event cannot silently replace it. The update-support guard may inspect an exact `current_npc` quote in the proposed reply, without promoting that draft into original history or native execution proof. Shared qualifiers or numbers also need surrounding content anchors: “before I lock the door” is not support for a kiss before departing a city, and sixteen parcels do not establish sixteen received letters. Such unsupported specificity stays incomplete while usable dialogue remains intact. These lexical sufficiency checks are conservative guards, not general entailment certification.

Local proof now includes explicit same-actor meeting-order reversals and unambiguous present-spouse conflicts with a nonempty supplied native spouse ID. Questions, uncertain/negated recalls, conflicting self-reports, different historical episodes and empty/unmodeled native households do not authorize these corrections. One bounded main-writer repair handles proven errors; failure removes only the proved false clause and dependent citations while retaining usable speech. Factual writes adding unsupported order, exact counts or named departures are held as incomplete with their proposed content and source gaps in the receipt. The comparator alone cannot quarantine a claim as false or choose relationship/action effects.

The writer's protected role evidence includes bounded, source-pinned player clarifications followed by explicit NPC acknowledgment. Conflicting earlier recollections stay historical mistakes. This projection changes future interpretation without changing original campaign records; corrections affect only their subject and do not resolve separate concerns or establish native results.

An explicit `dialogueClaimWorkBudgetMs` clamps to 500–15,000 milliseconds and is never silently extended. Without that setting, the server starts with an 8,000 ms allowance and grants bounded content-based headroom up to 15,000 ms for larger selected comparison sets; this is an allowance, not a latency forecast. The caller adds 2,000 ms and the request carries the same budget to the worker. Receipts identify configured versus default allowance. A fixed eight-pair development probe with complete 206–244-token documents scored 1/8 at 2 seconds, 5–6/8 at 8 seconds, and 8/8 at 15 seconds (11.3–12.4 seconds of warm inference); these repeated timing controls do not certify general coverage. Startup warm-up is separately timed and reported; caller wall time still bounds cold-load failure. Existing nonblocking ownership and exact-pair cache remain. An inference finishing late returns `late_scored` with diagnostic scores, unresolved acceptance and no new cache entry; these scores cannot retroactively authorize effects.

Receipts retain worker duration, load duration and cold/warm status separately from caller latency when the qualified worker reports them. Supported claims, unsupported hints and unresolved claims are separate counts. Comparison coverage belongs to the proposed response before effect quarantine. A later exact correction, writer revision or false-clause withholding records that final semantic coverage was not rechecked; revalidating source-proven violations is not a second classifier pass or a full semantic certificate.

Canonical `RunDialogueClaimEvidenceAssertions` joins the existing claim-validation suite. It exercises relevant source spans, complete questions/answers, missing evidence and capacity, chronology corrections, native-marriage negative controls, specificity quarantine, true-quote/extra-fact drift, acknowledgment pinning and failed-rewrite conversation preservation. Worker contracts exercise budget validation, cold/warm separation and late diagnostics. Local fixed-manifest model probes are development evidence, not independently labeled holdout or native acceptance.

Validated complete comparisons also guide an existing writer repair for an independently proven speaker inversion. Only comparisons matching the exact visible claim hash, original source ID and source hash enter the repair request, with original comparison text, canonical identity aliases and model scores. Foreign, malformed, unavailable and over-budget results supply no guidance. Scores do not create new violations or extra writer calls, and cannot expand the repair or replace the original-source ledger. Local exact corrections still avoid a writer call. Receipts retain `repairEvidence` and `repairGuidanceCount` so this active use is observable.

`dialogueClaimValidation` records coverage, original hashes, candidate spans, bounded comparisons, unresolved claims/addressees, withheld effects, latency and exact corrections. Corrected receipts hash final visible marked prose. `semanticAccuracyCertified` is false: deterministic contracts, development classifier probes and compilation do not establish held-out conversation quality.

Canonical product verification includes `RunDialogueClaimValidationAssertions` through `prompt_efficiency` and worker `ClaimValidationContracts` through `test_precision.py`. Run the existing memory, relationship, intoxication, correspondence/route and Save Sync suites from the retained artifact. Model quality benchmarks use fixed manifests and local CPU inference, without providers or campaigns. Record false accusations, misses, abstentions, cold/warm latency and memory separately. Independently labeled holdouts and post-deployment native/human acceptance remain separate requirements before broad paraphrase-based correction could be enabled.
