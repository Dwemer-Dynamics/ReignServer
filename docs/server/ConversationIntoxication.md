# Conversation intoxication and action text

NPC tolerance is `max(5, Endurance * 2.0)` serious-drink equivalents. At 50% the character is very intoxicated; 75% is severe; 100% is overwhelmed, sick and intermittently conscious. The server suppresses sustained replies and actionable commitments at 100%, rejects further alcohol, and retains the alcohol restriction until recovery below 50%. Recovery removes one equivalent per two campaign hours, never per chat turn. Only the native attributes.endurance value (or its native sourceFacts copy) supplies tolerance; Athletics and constructed traits never supply it. Absent attribute data uses the minimum.

Individual dialogue and the shared Party Chat/Castle Chat/social-event route append authoritative physical state after prompt compaction. The response supplies `drinkingEvents` with `actionIndex` (index among asterisk-marked actions), `serving` (`drink`, `half`, `sip`), integer `count`, `completed` and `alcohol`. One drink is 1, half is 0.5, a sip is 0.25. Only the current NPC's completed consumption in its accepted reply is eligible. Offers, refusals, recollections, hypothetical or uncertain events, water, non-actions and invalid quantities fail closed. Another character's choices cannot be authored by the current speaker. Dialogue narration has no authority to set arbitrary intoxication state.

`conversation_intoxication` stores one physical-state row per character in the campaign database. `conversation_drinking_turns` retains receipts keyed by hero and timeline/turn identity. Row locking and one transaction commit the new state with its receipt. Replays return the committed visible reply without consuming again. Save Sync clones the campaign schema: restored intoxication and receipts travel with the native save, and a subsequent history branch inherits the restored physical state. Missing clocks never advance recovery; stale clocks cannot add drinks. No native save format or game movement/animation is changed.

Receipts use `reign-drinking-receipt-v1`; state uses `reign-conversation-intoxication-v1`. Receipt fields include proposed/consumed amount, evidence rejections, stale-clock status, final state, commitment suppression and accepted reply. Private prompt values must not be spoken as character knowledge.

`ReignActionText` preserves mixed action/speech ordering and paragraphs. Balanced single `*action*` markers become only `<span style="Action">` tags. Unmatched or escaped markers stay literal. Unmarked historical prose is not reclassified. Supplied angle brackets are neutralized before native markup generation. The four chat surfaces use native `RichTextWidget`, upright `ReignSerifDynamic` and the matching genuine Cormorant Garamond Medium Italic `ReignSerifActionItalic` for actions. Brush sizes match their previous 15/16/17-pixel body roles. Player and system messages stay upright.

## Verification and remaining native acceptance

Obtain an exact-path MCP validation plan, then run `reign_validate`. From its successful Release artifact, run `reign_run_offline_verification` with `tier=quick`, `suite=conversation_intoxication`, and confirmation `run isolated offline verification`. The contract also runs in the contracts suite and the existing motive-conversation test route. It uses a uniquely owned fixture campaign inside the verifier sandbox; no provider or real campaign is used.

Run `node ReignBeta/tools/GauntletXmlPreviewer/test-conversation-actions.mjs` for format, markup safety, font packaging, four-surface bindings and testing-catalog drift. Run the shared preview, layout/portrait, typography and rendered-matrix audits. `build-runtime-sprite-sheets.ps1 -Categories ui_reignbeta_action_fonts` updates only the new font category while retaining the other manifest entries; a full manifest must already exist.

After deployment, native acceptance must verify wrapping, italics, scroll/reopen behavior, character-specific drinking in each route, threshold refusal, campaign-time recovery, and save/load rollback using an explicitly authorized disposable campaign. Provider-backed dialogue quality remains separate from deterministic engine proof. Do not claim those checks from compilation or browser previews. Do not stop the user's game/server or deploy without the agreed shutdown handoff.
