# Control Center saves and server power

Save Changes saves settings and every edited prompt in the prompt library, including edits retained after changing the selected prompt or page. Save Selected Prompt saves only that prompt. These controls preserve the exact submitted text. Reload Prompts refreshes saved versions while retaining drafts; Discard Selected Edits explicitly replaces that draft with the server copy. Browser refresh/close warns while a prompt draft remains. Castle Chat's paired prompt editor retains its separate Save Both control.

The prompt API validates every name/text and expected baseline before writing, atomically replaces each prompt file, invalidates the prompt cache, and acknowledges the text read back from disk. A concurrent edit is rejected unless the desired text is already stored (safe retry after a lost response). Multi-file saves are not a transaction: if an I/O error occurs partway through, completed files remain saved, remaining drafts are retained, and the UI reports failure. No prompt text is added to operational logs. The existing server-owned private prompt directory and umask stay in force.

Turn Server Off / Turn Server On controls the existing `reignserver.service`, including its vector worker, through Apache at port 8089. Apache and the launcher keepalive remain available. Reloading the page while the server is off shows a small start page; it returns to the full Control Center after verified health. A fully stopped WSL distro still needs its Windows launcher. Closing a browser tab leaves the service running.

Launcher behavior chosen on 2026-10-03: `scripts/Start-ReignServer-Wsl.ps1 -OpenControlCenter` opens the URL in the user's ordinary default browser. It selects no Edge app window, dedicated browser profile or browser-close shutdown. The launcher verifies installation identity, version, protocol, database and current schema. A healthy server is reused without another server start, including an existing Reign instance outside systemd. A Windows startup mutex serializes repeated shortcut clicks. If the local Chrome Control Center is already open, the launcher selects its existing REIGN tab, restores a minimized window and brings it forward. It checks the address bar for localhost or 127.0.0.1 on port 8089; an existing window activation failure cannot create a duplicate tab. A new ordinary default-browser page opens only when no existing local Chrome UI is found. Startup failures remain in a readable dialog.

An unhealthy/offline server is recovered before restart: stop the exact managed unit to disable automatic restart, resolve the installed `reign-recover.py` companion through WSL, acquire the canonical runtime lease, and identify only this installation's Reign executable under `runtime/current` or a valid retained version, running as `reign` with its owned Linux session/group and the production port-5101 invocation (including its plain default). Non-listening verification/discovery and other ports are excluded. Recovery includes same-user members of those sessions and exact first-party vector-worker script processes. Linux starttime and a process descriptor protect against PID reuse. It sends TERM, waits five seconds, then sends KILL only to still-live identified processes, with a further three-second bound. Exited zombies are complete. It does not kill an arbitrary port owner, clear a PID file/lock or alter campaigns/settings/runtime artifacts. A conflicting lease or foreign listener remains an explicit failure. This local root launcher route does not expand Apache's sudoers or browser command privileges. The failure state is reset only if the exact unit reports failed; a stopped/unloaded unit has no failure state to reset. The managed service starts only after recovery succeeds; health must become ready within 60 seconds before the UI opens.

The startup probe also exercises two real, nonmutating `wslpath` conversions, including a Windows path with spaces. Three injected UI cases prove existing-window activation, missing-window creation and no duplicate on activation failure; native browser adapters are compiled without desktop interaction. Four tab-name cases retain Chrome memory-usage suffixes and reject unrelated names. Discovery is limited to the native browser toolbar and tab strip. Three injected failure-state cases cover failed reset, inactive/unloaded skip and reset failure propagation. Recovery resolution normalizes Windows separators and uses WSL `--exec` to bypass Linux shell parsing. These probes run through canonical `ControlCenterRuntimeTests` and start no real listener/browser/provider. Authorized live acceptance must cover cold startup, healthy reuse with unchanged PID, unhealthy recovery with a new PID, ordinary default-browser rendering and loaded 384-dimensional worker health. The two launcher files must be deployed together with hashes and rollback evidence; no Linux executable or client replacement is required for this launcher-only change.

`scripts/install-reign-control.sh` installs the reviewed, root-owned `/usr/local/lib/reign/reign-control.py`, checks a narrow sudoers entry, and configures Apache's CGI exception ahead of its application proxy. Only the two exact `systemctl --no-block start/stop reignserver.service` commands are allowed for `www-data`. No generic shell, unit selector, arbitrary arguments, data access or general `reignctl` privilege is exposed. The CGI validates loopback or the exact WSL default-gateway peer, localhost port-8089 Host, same Origin, JSON body, and the `X-Reign-Control` header. It does not allow CORS; nonlocal/foreign-origin and arbitrary actions fail before command execution. Status reads fail closed on missing or unmanaged service state. Requests are bounded and commands are argument arrays. The offline page reads only the two fixed UI files in the current artifact.

## Startup PID and WSL login prerequisites (2026-10-05)

The root lifecycle controller creates `/run/reignserver` as root:root 0755 and `server.pid` as root:root 0644. It redirects the unprivileged launcher's PID output itself; the `reign` shell never opens the root PID record. This permits reuse of a stale root-owned record after the existing ownership/foreign-listener checks, while preserving unprivileged server execution and systemd's trusted PID contract. Symlinked/nonregular PID paths fail before writes. The runtime lock is neither replaced nor removed. A failed child launch removes only its newly initialized PID record.

The dedicated Debian WSL installation needs `libpam-systemd` and `dbus-user-session`: without PAM session registration WSL can time out waiting for root/reign user sessions even though system services later start. The control installer deploys and runs the root-owned `prepare-systemd-sessions.sh` before replacing service controls; `reignctl prepare` uses the same helper. The helper installs explicitly missing packages, checks final package status and active `pam_systemd.so` in `common-session`, and fails visibly for package-manager errors or disabled PAM. It does not rewrite authentication rules, enable lingering users, mask user services, change global WSL settings, or run from the launcher/browser. Apache keeps only its two fixed-unit sudo commands.

`StartupPrerequisiteTests` in `test-reign-control.py` runs through canonical MCP validation. The PID regression uses real root/reign identities, a disposable directory and an immediately exiting non-listening fixture. Package/configuration cases inject fake tools and never install packages or change user managers. Deployment acceptance must verify both package/PAM prerequisites, a fresh dedicated-distro launch without `CreateLoginSession` timeouts, managed server/worker stop/start, PID ownership, current database schema and the loaded 384-dimensional worker. Keep deployment held while the user's server is running.
