# Pregnancy context and exposure

Delayed correspondence projects canonical timeline state and observer knowledge available by its composition day; future snapshots/discoveries are excluded. Native sync rejects an unloaded request's campaign/timeline before capture, and checks ownership again before applying its response. Accepted party-banter lines carry the same bounded disclosure metadata even with ordinary gameplay effects disabled; drafts grant no knowledge. Verified Save Sync recovery retains only knowledge present in the restored snapshot with a matching sequence/head, including fractional campaign days.

`POST /family/pregnancy/sync` is the authenticated native client's bounded reconciliation route. It accepts the exact campaign/timeline/world day, at most 256 active native/managed pregnancy snapshots, native conversation observers and mothers actually present. It returns observer-specific prompt projections and source-backed knowledge for the current client save. It makes no provider call and never creates a native pregnancy or delivers a child.

Native truth records and observer knowledge live in `conception_contexts` and `conception_knowledge`, within the Save Sync relationships domain. The client saves native observations separately from managed conceptions. Current native state determines active pregnancy; missing parentage, historical marriage or timing remains unknown. The mother knows immediately. At 50% of supported pregnancy duration, an actual physical observer recognizes pregnancy, with paternity still separate. Conception history has participant-only knowledge, including repaired automatic realm-news projections from older versions.

Every speaking route receives mandatory live pregnancy context. The mother can intentionally conceal pregnancy before it is obvious and can misrepresent paternity; canonical biological/legal parentage never changes because of a claim. Group prompts label private speaker context. Correspondence never creates physical observation. Optional `pregnancyDisclosures` entries bind pregnancy identity, fact kind and exact affirmative speech to an accepted conversation source or actually delivered letter. Drafts, private reasoning, denied/uncertain statements and unsupported paternity do not grant confirmed knowledge.

The existing composer exposes `expose_concealed_pregnancy` with `pregnancyId` and `disclosure` (`mother_only` or `name_father`). It is the player's own standalone immediate declaration. Preview and commit validate active illicit pregnancy, current save knowledge, the approached parent and separately confirmed father identity. Mother-only exposure never names the biological father publicly. Approaching the father requires known paternity and names both parents. A successful native declaration persists before the response is generated, creates public history and activates The Unchaste: mother -50, named biological father -5. No extra Affair or deceived-husband penalty applies; ordinary pregnancies between spouses cannot be exposed. Retry, birth and seasonal reconciliation do not stack the same tag. Public disclosure flags carry into child parentage without changing marriage or recorded legal parentage.

Use canonical validation and immutable-artifact `prompt_efficiency` results, including `pregnancy_context_*`, for offline proof. Native existing-save, actual generated replies, action clicks and save/reload/birth require separate observed acceptance. Runtime snapshots and diagnostic payloads contain private family information and retain their existing access controls; public event payloads must not copy concealed father identity.
