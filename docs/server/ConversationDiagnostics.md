# Conversation Diagnostics

Open **Diagnostics → Conversation Diagnostics** in the Control Center. Select a conversation, then expand an NPC response to see the processing timeline. Each step explains its outcome; expand its input or result to read complete evidence, compare before/after values, or download the retained payload. Parent timings include child timings, so they must not be added together.

**Save all LLM information for debugging** defaults off. Enabling it persists across server restarts and records new responses, including background text model calls. Responses already in flight keep the capture setting they started with. Captures remain until manually cleared. The page shows disk use and capture failures. Its export includes private character context, rejected answers and any reasoning the provider returned. Credentials are removed before storage. It cannot recover information the provider never returned or original responses from before capture was enabled.

Ordinary audit logs remain sanitized. The separate store is `data/diagnostics/conversations`: `capture.json`, per-response manifests, append-only `steps.jsonl`, and compressed immutable payloads with character counts and SHA-256. It is outside campaign snapshots, game state and ordinary support bundles. Manifests retain readable final dialogue and step summaries with capture disabled. Historical audit entries are explicitly partial. No model generates explanations: rejection details come from the actual checks and repair decisions. The server delivery receipt does not claim the game rendered the response.

Operational logging and log read/export redact provider-qualified credentials such as NanoGPT, OpenRouter and vector API keys recursively, including old settings rows. Historical files are preserved; the sanitized read/export is a projection. This does not retract an earlier disclosure or replace credential rotation. The immutable full-conversation capture retains its separate credential-removal and content-hash rules.

The page supports campaign/type/outcome/date filters, text search, bounded paging, optional live refresh, explicit export and clearing the currently loaded completed captures. Changing filters clears the selection and disables its export/clear controls; delayed refresh results cannot restore it. Clearing cannot remove in-flight traces or campaign history. Restart-interrupted work is identified rather than reported as successful. Storage failures are visible and cannot reject a gameplay answer.

Read APIs are `GET /api/diagnostics/conversations`, `/trace`, `/payload`, `/capture` and `/export`. Payload reads require exact `traceId`/`payloadId` and return at most 12,000 UTF-16 characters; follow `nextOffset` without splitting surrogate pairs. Hashes describe the complete retained credential-redacted UTF-8 text. `POST /capture` accepts an `enabled` boolean. `POST /clear` requires 1–500 exact completed trace IDs and `confirmation: "clear selected diagnostic captures"`.

MCP exposes only the read tools `reign_query_conversation_diagnostics`, `reign_get_conversation_diagnostic_trace` and `reign_get_conversation_diagnostic_payload`. Only the last tool preserves the server's immutable `content` string without another prose redaction pass; envelope metadata retains standard secret redaction. The server removes real credential fields and the active provider key before persistence, while preserving fictional secrets and returned reasoning as requested.

Validation uses canonical manifest-selected Release validation and the exact artifact's `interaction_architecture` suite. Its `diagnostic_*` cases write a unique private fixture directory beneath isolated `VerificationDir`, never production data. Run `conversation-diagnostics-ui-contract.mjs` with the emitted `control-center.html`, `browser-fixture.json` and a task-owned output directory; also run the full `control-center-ui-contract.mjs`. Both use intercepted local browser traffic at 1672, 1024 and 600 pixels. Evidence includes assertions, rendered states and full-page frozen-palette checks. These web-only changes have no native raster, prefab or portrait requirement. Deployment and live provider/game acceptance remain separate.

### Local extraction and life-state diagnostics

Worker health includes `memoryExtractor` with configured/loaded/model hash/status/cache count and zero remote calls. `/memory/extract` is an internal loopback endpoint; never publish it independently. A successful HTTP envelope with `ok:false` is unavailable, busy or rejected input, not verified memory. Extraction responses bind source ID, SHA-256, schema and UTF-16 spans. Candidate tags do not authorize an action, relationship score or permanent trait. Model loading never downloads at request time; missing local files/dependencies preserve the existing conversation path.

The server records `memory.specialist_index_deferred`, `memory.specialist_reconcile_deferred`, `character.life_read_unavailable` and `character.life_projection_deferred` without logging private source text or credentials. Per-request `characterLifeState` reports selected source IDs/counts or unavailable status. A lookup or projection failure cannot erase prose or justify a penalty. Source-backed life transitions have a separate dynamic category from soft personal canon; cached projections are revalidated against original accepted turns, letters and native events on read. See `SpecialistMemory.md` and the paired dialogue testing procedure.
