# Precision memory

The PostgreSQL source ledger remains authoritative. Full original turns and native receipts are retained; summaries, temporal assertions, directional projections and vectors are replaceable read models. A quotation proves speech. Only native receipts prove game effects. Failed visible repairs remain readable speech and cannot authorize structured writes or actions.

`MemoryContextV2.cs` implements entity/query planning, observer/time eligibility, ranked SQL plus optional semantic retrieval, linked original exchanges, complete-record allocation, provenance aliases and final-content checks. Ordinary dynamic evidence targets 2,000–4,000 estimated tokens, with 8,000 or the required floor when necessary. Context-capacity certification still controls the final serialized request. These are estimates, not claims about model-specific tokenizer counts.

Directional foundation projections carry source revision, accepted-turn sequence, timeline, observer/peer and restore/projection generation. Cached values are reused only for matching context and source state. Save Sync changes the restore generation, invalidates projections and rebuilds vector jobs. Background jobs use source/version/generation identities, 120-second leases, 30-second heartbeats, 60-second reconciliation and four attempts. Incomplete compaction retains source records and remains visible as incomplete.

Default campaign mode is `shadow`: the production response stays on the existing path, and the precision comparison makes no additional paid helper calls. `legacy` disables the comparison. `precision` selects the new evidence packet. Changing mode uses a reviewed `set_memory_mode` maintenance operation with the complete expected state. Each transition increments projection generation; reverting mode never restores an old campaign database.

## Staging and recovery

Use the validated artifact with `scripts/Repair-ConversationContinuity.ps1`. `-Mode Stage` accepts a `reign-memory-stage-request-v1` containing the exact `campaignId`, `timelineId` and optional `sessionIds`. A read-only serializable transaction creates an extractive reconstruction artifact, source hashes, complete-record coverage, ambiguity report and token estimate. No provider call or production write occurs. The resulting `reign-continuity-repair-v1` is the input to `Preview`, which applies then rolls back the exact operations.

`Apply` retains the wrapper's stopped-game/service check, verified `pg_dump`, exact manifest and executable SHA256, source comparison and restore-generation gate. Only reviewed derived operations are allowed: rebuilding scene summaries, changing the read mode, scoping private assertions, recovering accepted agendas and quarantining derivatives. Original transcript, native receipts and relationship scores are outside this vocabulary. A predeployment stage with an uninitialized generation must be regenerated after schema deployment. Unresolvable old semantics remain explicitly uncertain; reconstruction must not invent beliefs, consent or completed actions. Keep artifacts and campaign text in ignored private evidence storage.

The wrapper executes maintenance as the managed `reign` Linux account, with PostgreSQL peer authentication on `/var/run/postgresql` and the explicit `reign` database. Run-owned incidental CLI files stay under `EvidenceDirectory`. It neither relies on legacy TCP credentials nor changes database roles, credentials or services. Canonical wrapper fixtures exercise Stage/Preview identity binding, wrong-artifact rejection and the running-service/BLSE game Apply gates before the real read-only campaign preview.

## Local ranking and validation

The BGE-small 384-dimensional index uses overlapping tokenizer windows of 448 source tokens with at most 48 metadata tokens. The worker refuses windows exceeding 512 tokens, preserves source spans and rechecks eligibility before ranking. Upsert inference yields between four-window batches. PostgreSQL revalidates source hash and generation before accepting vector evidence. External Qdrant uses [document grouping](https://qdrant.tech/documentation/search/#grouping) before the result limit so a long document's chunks cannot consume every result slot. Source-bearing exchange retrieval similarly counts eligible complete exchanges after excluding recall-only sessions. Temporal assertions apply regional public scope before counting candidates.

Optional `enableMemoryPrecisionCrossEncoder` requests at most 32 eligible candidates from `cross-encoder/ms-marco-MiniLM-L6-v2`. The worker requires `REIGN_MEMORY_RERANK_MODEL_DIR` (local `model.onnx` and `tokenizer.json`) and `REIGN_MEMORY_RERANK_CERTIFICATE`. The certificate must use `reign-memory-rerank-certificate-v1`, match both artifact hashes, identify a held-out corpus of at least 100 cases, have zero critical errors and at least 98% required-fact coverage, improve quality over baseline and keep p95 within 20% of baseline. Missing/invalid certificates leave SQL/hybrid ranking in place. Long candidates retain their original rank instead of being prefix-truncated. No model downloads or paid calls occur implicitly. Model references: [model card](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2), [ONNX Runtime](https://onnxruntime.ai/docs/api/python/api_summary.html).

Canonical MCP tests execute `test_precision.py` without model inference, then exercise the managed BGE tokenizer and in-memory Qdrant filter parity through the dedicated WSL Python runtime. Retain `prompt_efficiency`, relationship and Save Sync results. Offline fixtures do not prove human roleplay quality, provider answer accuracy or the held-out 40% median total-input reduction target. Experimental reranking remains disabled until that separate measured acceptance succeeds.
