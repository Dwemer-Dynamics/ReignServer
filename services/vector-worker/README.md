# Reign Vector Worker

Local archive loading uses the first-party `compact_store.py` adapter with pinned Qdrant 1.14.2. It streams the existing SQLite PointStruct records into float32 arrays instead of fetching the entire archive and retaining Python float lists. The normalized search matrix shares native payloads and retains no extra per-point vector arrays. A complete document-to-chunk map makes background replacement delete only the identified native points, without two whole-archive filter scans. Native persistence, exclusive lock, source eligibility and full-history search remain unchanged; no third-party package patch or destructive migration is used. Health reports `localArchiveLoader` and compact collections. Canonical runtime contracts cover native-load/search/visibility/persistence/rollback parity and lock ownership; incompatible versions/configurations fail explicitly. See [dialogue testing](../../../Reign/docs/agent/testing/DIALOGUE_AND_PROVIDERS.md) for resource measurement and native acceptance limits.

Local dialogue validation: `POST /dialogue/claims/compare` supplies hash-bound CPU NLI comparison hints for at most eight complete short pairs. `POST /dialogue/claims/extract` supplies exact GLiNER2 claim-role span candidates from at most 256 tokens. Both are loopback-only, fail open for conversation delivery and have no actor/action authority, provider calls, database access or implicit downloads. Health reports `dialogueClaimValidator`; startup warm-up is independent of server availability. See [DialogueClaimValidation](../../docs/server/DialogueClaimValidation.md) for asset pins, bounds, privacy, coverage and qualification limits.

Optional grounding: explicitly select `REIGN_DIALOGUE_CLAIM_MODEL=minicheck` and a separately staged, pinned `REIGN_DIALOGUE_GROUNDING_DIR`. CPU FP32 ONNX uses the upstream document/EOS/claim format with a 256-token complete-pair bound. Unsupported is not contradiction; hints cannot block delivery or authorize effects. Default remains `nli`, `off` disables loading, and missing selected assets never fall back silently. The explicit offline `prepare_claim_grounding.py` recipe requires pinned local sources and fresh output; it has no runtime download, campaign or provider access. Review accuracy/resource evidence and obtain deployment approval before managed activation.

Local selection: `POST /memory/selection` runs pinned Qwen3-Reranker-0.6B relevance or LLMLingua-2 extractive salience. Requests bind exact UTF-8 text hashes (including whitespace) and, for compression, complete UTF-16 source-span partitions. No generated prose, campaign writes or implicit downloads. Bounds: 32 candidates, 160,000 total characters, 100–30,000 ms deadline, 100 ms lock wait, two CPU inference threads and 256 cached results. Ranking selects an explicit `backend` of `cpu` or `cuda`; compression uses `cpu`. CUDA uses a 2 GiB arena limit; CUDA context/driver allocations are additional. No silent CPU substitution is accepted. Complete ranking, backend and ONNX Runtime 1.22.0 are source-bound receipts. Cache identity includes backend; incomplete results fail as a unit. The helper's lock is separate from Qdrant and ColBERT. Health reports `memorySelection` installation, loaded operations, cache and outcome.

Explicit preparation derives a hash-pinned Q4/F16 binary-score Qwen graph using `scripts/Prepare-MemorySelection.py`: retain the pinned Q4 weights, convert floating tensors to FP16 and materialize only the last-position no/yes logits. This quantized graph requires its own accuracy qualification. The worker loads models lazily. CPU/GPU timings, cold loading and game contention must be measured separately; installation and synthetic inference do not establish held-out qualification. See [SpecialistMemory](../../docs/server/SpecialistMemory.md).

Ranking policy `complete-source-window-max-v1` scores complete records directly up to 2,048 total tokens, or completely covers longer originals with at most 16 overlapping source slices. All slices must finish before returning the strongest relevance score; full original evidence remains authoritative. Receipts include UTF-16 coverage ranges. GPU runs shrink unused arena regions after inference. The default deadline is 15 seconds including cold load; it is not a deliberate delay for warm requests.

The server requests compression only for budget-rejected records whose protected-span minimum can fit. Fitting originals and hopeless compactions make no compressor request. Server receipt validation requires complete scoring ranges without gaps or split Unicode surrogate pairs. Prepared compact views are distinct from views actually selected into the writer prompt.

Managed local semantic-memory worker using FastEmbed's ONNX `BAAI/bge-small-en-v1.5` model and persistent local Qdrant or an explicitly configured external Qdrant service.

Release builds include the model. The installed launcher sets `REIGN_VECTOR_MODEL_DIR`; that mode requires complete local files and never downloads a replacement. Development without that variable retains the original download cache behavior.

The supported server runtime is Linux. Managed `reignctl prepare` installs `requirements-linux.txt` into a requirements-hash-specific environment and verifies `release/embedding-model.lock.json`; it preserves the prior environment for rollback. FastEmbed-GPU supplies the shared ONNX Runtime distribution, but BGE and ColBERT explicitly remain on CPU. Only a CUDA-qualified Qwen request uses the GPU. Do not mix CPU/GPU ONNX distributions in one environment or recreate the retired Windows server package. The legacy Windows lock is not a Linux deployment recipe.

Precision memory uses versioned token windows and observer/timeline/restore-generation filters before top-k selection. Whole original sources remain in PostgreSQL. Canonical MCP validation runs `test_precision.py`, including managed BGE tokenizer and in-memory Qdrant parity contracts. See [precision memory](../../docs/server/MemoryPrecision.md) for opt-in cross-encoder certificates, isolation, maintenance gates and limitations. No test or worker path downloads a reranker implicitly.

The pinned ColBERTv2 ONNX assets add original-dialogue discovery through the same local service. Its self/public token-vector cache is rebuildable; exact caller-approved source hashes filter before scoring, and PostgreSQL originals remain authoritative. Default shadow mode, qualification, endpoint bounds, fallback and source-linked replay are described in [specialist memory](../../docs/server/SpecialistMemory.md). RAGatouille, PyLate, GPU runtimes and remote generation are not dependencies of this path. ColBERT contracts run under canonical runtime validation; passing storage/privacy contracts is not a semantic quality certificate.
