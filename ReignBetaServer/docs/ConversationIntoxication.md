# Conversation intoxication and action text

NPC tolerance is `max(5, Endurance * 2.0)` serious-drink equivalents. At 50% the character is very intoxicated; 75% is severe; 100% is overwhelmed, sick and intermittently conscious. The server suppresses sustained replies and actionable commitments at 100%, rejects further alcohol, and retains the alcohol restriction until recovery below 50%. Recovery removes one equivalent per two campaign hours, never per chat turn. Only the native attributes.endurance value (or its native sourceFacts copy) supplies tolerance; Athletics and constructed traits never supply it. Absent attribute data uses the minimum.

Individual dialogue and the shared Party Chat/Castle Chat/social-event route append authoritative physical state after prompt compaction. Only the speaking NPC's completed consumption in an accepted action paragraph is eligible. Offers, refusals, preparations, quoted/reported speech, historical events and other actors never establish consumption. This accounting does not constrain invented backstory, embellishment or in-character self-correction.

## Beverage and action contract (2026-09-15)

`ConversationBeverages.cs` owns the versioned `reign-beverages-v1` catalogue. It records native/Reign provenance separately from compatibility vocabulary: beer/ale, wine/hippocras, mead/honey wine, kumis/koumiss/airag/fermented mare's milk, fruit wines/cider/perry and legacy spirits. Kvass and boza require an explicitly alcoholic preparation; ordinary milk, water, tea, sherbet, vinegar and alcohol-free variants stay nonalcoholic. Availability remains a scene decision. This catalogue does not introduce items, prescribe regional customs or guess alcohol strengths.

The consumed object controls identity. Watered wine and tea mixed with brandy contain alcohol; water beside wine does not. A fictional name can identify a drink when the action defines its preparation. An unknown name or unknown variant does not become alcoholic merely because the model sends `alcohol:true`. Current accepted vessel context, or an unambiguous current sharing/drinking fact, may resolve a generic cup. History, player narration and ordinary dialogue cannot establish contents.

The response supplies `drinkingEvents` with `actionIndex` among **all** asterisk actions, an exact complete `actionQuote`, `occurrenceIndex` among this NPC's consumptions in that paragraph, optional exact `evidenceQuote`, `serving` (`drink`, `half`, `sip`), integer `count`, `completed` and `alcohol`. The server independently extracts consumption occurrences. A unique exact quote repairs a wrong paragraph index. Legacy index-only entries may bind to one uniquely matching consumption. Ambiguous/deleted metadata is never retargeted by guesswork; independently verifiable final narration can still count. Taking a mouthful and swallowing it is one occurrence; two distinct sips are two.

## Amounts and vessels

Explicit narrated quantity wins. Sip, mouthful, pull, swig, gulp and draught default to 0.25; half a cup is 0.5, half a mouthful is 0.125, a full ordinary cup is 1. Explicit positive counts are bounded at 20 per occurrence. Compatible valid metadata fills genuinely unspecified volume. Without either explicit volume or compatible metadata, an actual drink defaults to 0.25. Invalid/exaggerated metadata cannot increase an explicit quantity or erase otherwise established consumption. No strength/ABV recalibration is included.

One unambiguous vessel is retained per NPC in the current conversation/location, for at most one campaign hour without a new accepted observation. A null remaining volume means unknown. Explicit refills/full cups establish volume for ordinary drinking vessels; pouring an unspecified amount leaves volume unknown. Bottles/jugs do not acquire an assumed one-serving capacity. Sips decrement known volume; finishing uses only the remainder; half of what remains is relative to that remainder. Refills, spills, switches and handoffs update contents without incrementing the alcohol counter. Ambiguous/replaced contents invalidate prior assumptions.

Existing client session/event IDs provide scope. A per-turn `sceneTurnId` is not reused as a session. When a stable identity is absent, references can still resolve inside the current reply, but cannot borrow a previous turn's cup. The physical intoxication counter persists independently of cup expiry.

## Persistence, prompts and audit

`conversation_intoxication` stores one state row per character; its optional `vessel` object adds contents, classification, nullable remainder, session scope, hour and catalogue version. Older rows load with unknown vessel state. `conversation_drinking_turns` retains receipts keyed by hero and timeline/turn. Row locking and one transaction commit both intoxication/vessel state and its receipt. Concurrent retries return the committed reply without changing state again. Save Sync clones this same campaign schema, restoring contents and receipts alongside intoxication. No historical receipt is reprocessed and no old missed drink is backfilled.

Missing/stale clocks cannot mutate cup context or add drinks. When a proposed reply is replaced by a refusal, its unseen refill/transfer is discarded. On reaching the threshold, the accepted amount is capped and vessel context is invalidated because the replacement reaction no longer supports the proposed details. Tolerance, recovery and the restriction until below half remain unchanged. Prompt construction reads valid current context without updating storage. Private counter/volume values are not spoken as character knowledge.

State and receipt schemas remain backward-compatible `reign-conversation-intoxication-v1` and `reign-drinking-receipt-v1`. New `drinking.receipt` evidence includes exact occurrence span, binding, catalogue/family/classification, beverage source, quantity source/normalization, proposed amount, accepted amount, remaining before/after and whether proposed vessel changes were committed. Non-consumption vessel observations also emit audit evidence. Repetition cleanup preserves repeated consumption and exact occurrence metadata while reindexing surviving action paragraphs.

Recognition uses bounded English clauses, pronouns/verified speaker names, quotation masking, consumed-object matching and conservative ambiguity handling. It is not a general natural-language parser. Unsupported wording remains observable in rejected/unknown evidence; no extra provider request is made to classify a drink.

`ReignActionText` preserves mixed action/speech ordering and paragraphs. Balanced single `*action*` markers become only `<span style="Action">` tags. Unmatched or escaped markers stay literal. Unmarked historical prose is not reclassified. Supplied angle brackets are neutralized before native markup generation. The four chat surfaces use native `RichTextWidget`, upright `ReignSerifDynamic` and the matching genuine Cormorant Garamond Medium Italic `ReignSerifActionItalic` for actions. Brush sizes match their previous 15/16/17-pixel body roles. Player and system messages stay upright.
